# training/

Feature tables and model checkpoints, all gitignored and regenerated by
`scripts/` (see the top-level README for the order). The best models are
published to Hugging Face via `scripts/export_models.py` →
`scripts/push_models_to_hub.py`. This folder holds the raw training-side
artifacts those are built from.

## Feature tables

- `features.parquet` is Model 1's table, from `scripts/prepare_training_data.py`.
  It has one row per (printing, finish) with a matched price, model-ready
  boolean/numeric/categorical features, `__target_log_price_avg`, and
  `__group_oracle_id` (the train/test split group key, not a feature). The
  feature decisions (what's dropped and why) are in that script's docstring.
- `features_model2.parquet`, `model2_text_emb.npy`, `model2_image_emb.npy`
  come from `scripts/prepare_training_data_model2.py`. They're Model 2's wide
  table plus row-aligned text/image embedding arrays. Tags are selected by
  frequency, which is the best-performing variant. Running the script with
  `correlation` writes the archived alternative,
  `features_model2_correlation_tags.parquet` (SPECS.md §4.2). **Never give one
  snapshot the other's filename.** They have the same column count but
  different column meaning, so a checkpoint loaded against the wrong one fails
  silently. Every `Config` records its own `features_path` for this reason.
- `pull_rate_defaults.parquet` comes from `scripts/build_pull_rate_defaults.py`.
  It's a (rarity, finish) → expected `{subtype}_rate_percent` lookup, so an
  unreleased card still gets a plausible pull-rate feature (SPECS.md §4.2,
  "inference input contract").

## Best checkpoints

- `model1.cbm` + `model1_calibration.json` is the best CatBoost:
  tier-A features, depth 6, lr 0.08, plus per-bucket conformal corrections,
  feature list and test metrics. It comes from `scripts/calibrate_model1.py`.
- `model2.pt` is the best deep-kernel GP (`train_model2.BEST_CONFIG`:
  full text+image+tabular, joint_dim 48, graduated $100–$1000 oversampling).
  It holds the feature-extractor + GP + likelihood state dicts plus the
  pickled `Config`, and comes from `scripts/train_model2.py`.
- Quantile-head alternative (unpublished): the tuned best is
  `tune_candidates_quantile/tune5_joint_dim=32_head_hidden_dim=128_lr=0.003.pt`
  (calibrated $10–100 71.1%, $100+ 65.9%). `model2_quantile.pt` is the older
  *untuned* run.

The other subfolders (`ablation_checkpoints*/`, `best_tactics/`,
`collapse_fixes/`, `inducing_sweep/`, `robustness_checkpoints/`,
`tune_candidates*/`) are checkpoints from the experiments in SPECS.md §4.2,
written by `scripts/experiments/`. They are superseded by the checkpoints
above and safe to delete. The experiment scripts recreate them on demand.

**Reproducibility caveat for legacy checkpoints:**
`robustness_checkpoints/correlation_tags.pt` and the `best_tactics/*.pt`
files were trained while `_explode_top_n`'s `frame_effects` fallback had
nondeterministic column order (since fixed). They only approximately reload,
with single-digit-point drift. Everything trained after the fix, including
`model2.pt`, reproduces exactly.
